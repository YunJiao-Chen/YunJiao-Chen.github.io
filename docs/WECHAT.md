# 微信公众号导出指南

把同一篇 Markdown 文章同时发布到**个人博客**与**微信公众号**，是本模板的核心能力。本文说明原理、两种用法、排版规范与常见问题。

---

## 1. 为什么不能直接复制网页

微信公众号后台编辑器是一个**受限的内联样式环境**：

| 网页里有 | 粘贴到公众号后 |
| --- | --- |
| `<style>` 标签、外部 CSS | 全部丢弃 |
| `class="prose"` 等类名 | 类名保留但样式不存在 |
| `style="..."` 行内样式 | ✅ 保留（唯一可靠通道） |
| `div` 容器 | 支持差，容易出现样式错乱（偏好 `section`） |
| `flex` / `grid` / `gap` | 不稳定或无效 |
| `<input type="checkbox">` | 被过滤（任务列表复选框会消失） |
| 外链图片 | 被过滤，需在公众号后台上传 |
| 站外超链接 | 不可点击（仅允许公众号文章链接） |

所以正确做法是：**在浏览器里把最终计算样式逐个元素写回 `style` 属性，再做一次结构降级**，然后以 `text/html` 写进剪贴板。

---

## 2. 用法一：文章页「复制到公众号」（写作时）

1. 打开任意文章页（`/blog/<slug>/`）；
2. 点正文下方的 **复制到公众号** 按钮；
3. 打开公众号后台 → 图文消息 → 正文，直接 `⌘V` / `CtrlV` 粘贴；
4. 再手动填写标题与摘要（按钮会把建议值一并给你，见下文导出页）。

按钮背后发生的事（`src/scripts/wechat-runtime.js`）：

```
克隆 [data-wechat-article] 正文
  ↓ 剔除站内元素（目录 / 操作按钮 / 评论 / 锚点链接 / 上下篇）
  ↓ 逐元素 getComputedStyle → 按白名单写回 style（字体/字号/行高/颜色/间距/边框/圆角…）
  ↓ 结构降级：div→section、复选框→✅⬜、h1→h2、表格补边框、图片居中
  ↓ 代码块：固定浅底 + 取「浅色 token」颜色（深色模式下导出依然可读）
  ↓ 包一层基准排版（正文 16px / 行高 1.75 / 中性灰 + 单一强调色）
  ↓ ClipboardItem{ text/html, text/plain } 写入剪贴板
```

白名单之外的属性不会被带过去（例如 `flex`、`position`、`transform`），这正是它比"直接复制"稳定的原因。

**降级方案**：同一行还有一个「下载 HTML」按钮，会导出一个独立 HTML 文件，可在浏览器打开后手动全选复制。

## 3. 用法二：构建期导出页（批量 / 离线）

```bash
npm run build      # astro build + 导出
# 或只重新导出
npm run wechat
```

产物：

```
dist/wechat/
├─ index.html                    # 目录页（标题 / 分类 / 日期 / 摘要）
├─ astro-personal-blog-rebuild.html
├─ markdown-to-wechat-pipeline.html
└─ ...                           # 每篇文章一个全内联样式的独立页面
```

每个导出页顶部有三个按钮：

- **复制到公众号**：把已内联的正文写进剪贴板；
- **下载 HTML**：另存为文件；
- **全选正文**：选中并提示手动复制。

页面顶部还会给出**建议标题 / 建议摘要 / 来源链接 / 分类 / 日期 / 阅读时长**，直接照着填公众号后台即可。

导出页是**自包含**的：CSS 已内联，脚本已内嵌，用 `file://` 双击打开也能正常一键复制（不需要联网、不需要起服务）。

### 只导出一篇

```bash
node scripts/export-wechat.mjs --only astro-personal-blog-rebuild
node scripts/export-wechat.mjs --check      # 只校验能否导出，不写文件
```

### 让某篇文章跳过公众号

在 frontmatter 里：

```yaml
wechat:
  enable: false
```

### 公众号侧覆盖文案

```yaml
wechat:
  title: 公众号里更口语的标题
  digest: 公众号摘要（不超过 120 字体验最好）
  author: 笔名
```

## 4. 排版规范

规范集中在 **`src/styles/wechat.css`**（导出的行内样式来源）与
**`src/scripts/wechat-runtime.js` 的 `SPEC`**（浏览器端一键复制的同款参数），两处保持一致：

| 元素 | 规格 |
| --- | --- |
| 正文 | 16px / 行高 1.75 / 颜色 `#3f3f3f` / 字距 0.5px / 段间距 16px |
| 一级小标题（`##`） | 19px 加粗 `#1a1a1a`，底部 1px `#ececec` 细线 |
| 二级小标题（`###`） | 17px 加粗 |
| 引用 | 左侧 3px `#d9d9d9` 细线 + 浅灰底 `#f7f7f7`，无彩色装饰 |
| 行内代码 | 等宽 13~14px，深灰字色 `#1a1a1a` + `#f5f6f8` 底 |
| 代码块 | `#f6f8fa` 底 + 1px 边框，保留语法着色，`white-space: pre-wrap` 防止横向溢出 |
| 表格 | 全边框 `#e5e5e5`，表头 `#fafafa` 底 |
| 图片 | `max-width:100%`，块级居中，圆角 6px |
| 链接 | 公众号链接色 `#576b95` |

改一处即可同时影响**站内文章排版**与**公众号导出排版**（`prose.css` 管站内、`wechat.css` 管导出，数值按上表对齐）。

## 5. 发布前检查清单

- [ ] 文章页点「复制到公众号」，粘贴到公众号后台草稿里通读一遍
- [ ] 代码块没有横向滚动丢失内容（本项目已设 `pre-wrap`，长行会自动折行）
- [ ] 表格在手机预览下没有溢出（列数建议 ≤ 4）
- [ ] 图片已在公众号后台重新上传，并补上图片说明
- [ ] 摘要（digest）已填写，朋友圈/会话列表里显示正常
- [ ] 原文链接填博客地址，形成「公众号 → 博客」回流
- [ ] 站内文章与公众号文章标题/内容一致，无残留草稿内容

## 6. 常见问题

**Q：粘贴后样式全丢了？**
A：确认用的是文章页/导出页的「复制到公众号」按钮（写入的是 `text/html`），而不是从浏览器地址栏复制文本。若浏览器不支持 `ClipboardItem`（少数旧版/Safari 隐私模式），脚本会自动降级为 `execCommand('copy')`，仍失败时用「下载 HTML」。

**Q：代码块里的颜色变成了浅色/深色不对？**
A：导出固定使用**浅色主题 token**（浅底深字，公众号默认白底可读）。站内深色模式不影响导出结果，因为运行时从元素原始 `style` 里读取浅色值而不是读当前主题的计算颜色。

**Q：中文标签 / 文章的链接在公众号里点不动？**
A：公众号仅允许跳转公众号文章。建议在正文末尾放一句"点击文末原文链接查看带目录与代码高亮的版本"，并把博客地址填进「原文链接」。

**Q：`dist/wechat/` 会被搜索引擎收录吗？**
A：不会。导出页带 `noindex,nofollow`，`robots.txt` 也 Disallow 了 `/wechat/`，sitemap 里也做了过滤。

**Q：能直接调用公众号 API 发草稿吗？**
A：可以，但需要 AppID/AppSecret、IP 白名单，且素材图片必须先上传到微信服务器。本模板先提供"复制粘贴"这条零依赖通道；如需自动化，可在 `scripts/export-wechat.mjs` 之后追加一个上传素材 + 新增草稿的脚本（路线图见 `docs/DESIGN.md` §11）。
