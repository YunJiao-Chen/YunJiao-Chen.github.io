## A 卡的特征分析有自己的红线

A 卡在申请时点出分，这个时点决定了它最硬的一条约束：所有特征必须在申请提交那一刻就能取到，且不依赖申请之后的任何行为。我见过最典型的翻车是入模了「放款后首期是否逾期」，离线算出来 IV 高得离谱，线上根本取不到数，整张卡回炉。

在这条红线之内，特征分析要回答四个问题：这个字段干净吗，它有区分度吗，它未来还稳吗，它和别人说的是不是同一件事。对应到四个环节，就是描述性统计、单变量效果、稳定性、相关性与共线性。

我现在的执行顺序固定成下面这样，每一步都有明确的产出和淘汰线。

| 环节 | 回答的问题 | 主要指标 | 典型淘汰线 |
| --- | --- | --- | --- |
| 描述性统计 | 字段能不能用 | 缺失率、单值占比、分位数、分组坏账率 | 缺失率大于 90%，单值占比大于 95% |
| 单变量效果 | 有没有区分度 | IV、KS、AUC、Lift、卡方 | IV 小于 0.02 |
| 稳定性 | 未来还准不准 | PSI、缺失率漂移、WOE 漂移 | PSI 大于 0.25 |
| 相关与共线性 | 是不是重复信息 | Pearson、Spearman、VIF、条件数 | 相关系数绝对值大于 0.7，VIF 大于 10 |

## 一、描述性统计分析

### 先把样本口径钉死

字段体检之前，标签本身要先对齐：观察点是哪个时点，观察期多长，表现期多长，坏样本怎么定义。A 卡的坏样本常见口径是「放款后前 6 期出现 M1+ 逾期」，那么申请日在近 6 个月内的样本表现期没走完，必须整段丢弃，不能用 0 填充。这一步做错，后面所有指标都是错的。

### 字段级体检看六个维度

| 维度 | 具体指标 | 我要看出的问题 |
| --- | --- | --- |
| 覆盖率 | 缺失率、缺失在好坏样本上的差异 | 缺失是随机的，还是本身就是风险信号 |
| 集中度 | 单值占比、Top 取值占比 | 字段是不是几乎只有一个值 |
| 分布形状 | 分位数、均值、标准差、偏度、峰度 | 长尾、双峰、被离群值拉偏 |
| 异常值 | IQR 越界比例、业务上限越界比例 | 特殊值编码，例如 -999、0.00、空字符串 |
| 区分度初查 | 按坏样本标志分组的分箱坏账率 | 方向和业务常识是否一致 |
| 可落地性 | 取数成本、数据源依赖、更新频率 | 离线高 IV 但线上取不到或延迟太大 |

几个常用公式：

```
缺失率     = 该字段缺失记录数 / 总记录数
单值占比   = 出现最多的那个取值的记录数 / 总记录数
变异系数   = 标准差 / 均值                     （均值接近 0 时不用，会失真）
偏度       = E[(X - μ)^3] / σ^3                （大于 0 右偏，小于 0 左偏）
峰度       = E[(X - μ)^4] / σ^4 - 3            （大于 0 尖峰厚尾）
分箱坏账率 = 该箱坏样本数 / 该箱样本数
IQR 越界   = 小于 Q1 - 1.5 × IQR 或大于 Q3 + 1.5 × IQR，其中 IQR = Q3 - Q1
```

### 这一步真正值钱的是分组坏账率

汇总统计只能告诉我字段长什么样，决策要靠分组坏账率。我习惯先按业务含义粗分箱，再看每箱的坏账率是否单调、是否有业务上说不通的跳变。一个字段在整体上很「健康」，但拆到某一段坏账率突然翻倍，这往往就是后面分箱要单独切出来的位置。

同时要核对方向。比如「近 3 个月贷款审批查询次数」越多越坏，「授信额度使用率」越高越坏，「年龄」在某个区间之后反而变好，这些业务先验是后面判断系数符号的依据。如果数据方向和常识相反，先怀疑口径，再怀疑数据，最后才考虑接受。

淘汰规则我一般定得比较粗，宁可先留着：缺失率超过 90% 直接剔，单值占比超过 95% 直接剔，IQR 越界比例超过 5% 且没有业务解释的降级为候选。

## 二、单特征效果分析

### WOE 与 IV

WOE 是把一个分箱映射成一个连续数值：这个箱里坏人占比相对于好人占比的对数比。IV 是各箱 WOE 的加权和，衡量整个字段携带了多少区分好坏的信息。

```
WOE_i = ln( (Bad_i / Bad_total) / (Good_i / Good_total) )
      = ln( (Bad_i / Good_i) / (Bad_total / Good_total) )

IV    = Σ_i ( Bad_i / Bad_total - Good_i / Good_total ) × WOE_i
```

其中 i 是分箱下标，Bad_i 与 Good_i 是该箱的坏样本数与好样本数。WOE 为正表示这一箱的坏账率高于整体，为负表示低于整体，绝对值越大偏离越远。

IV 的经验区间我一直用这张表，但只当入口条件，不当结论：

| IV 区间 | 区分度 | 我的处理 |
| --- | --- | --- |
| 小于 0.02 | 几乎没有 | 剔除，除非业务上必须保留 |
| 0.02 到 0.1 | 弱 | 作为辅助变量，单独评估业务价值 |
| 0.1 到 0.3 | 中等 | 主力候选 |
| 0.3 到 0.5 | 强 | 重点复核业务逻辑与口径 |
| 大于 0.5 | 过强 | 优先怀疑标签泄漏、时点穿越、分箱过细 |

### IV 最容易踩的三个坑

第一，IV 对取值个数天然偏高。同一个字段分 5 箱和分 20 箱，后者 IV 一定更大，但多出来的部分是噪声。所以 IV 要跟基数一起看，类别型字段我会额外看 Cramér's V。

第二，用全量数据算 IV 再挑变量，是标准的选择偏差。应该只用训练期算 IV，验证期和 OOT 只用来复核。

第三，也是我踩过最疼的一个，IV 只衡量区分度，不衡量稳定性。一个字段在训练期 IV 是 0.35，但它依赖的数据源在最近三个月改过口径，入模就是定时炸弹。所以 IV 之后必须紧跟 PSI。

### 单变量不只有 IV

不同场景下我会换着用这些指标：

```
KS         = max_t | F_good(t) - F_bad(t) |          好坏累计分布的最大间距
AUC        = P(坏样本的预测违约概率 > 好样本的预测违约概率)
Gini       = 2 × AUC - 1
Lift_前10% = 前 10% 分数段的坏账率 / 整体坏账率
卡方       χ² = Σ_i ( O_i - E_i )² / E_i             类别型字段与标签的独立性检验
Cramér's V = sqrt( χ² / ( n × min(r - 1, c - 1) ) )   类别型关联强度，取值 0 到 1
```

IV 偏向连续分箱后的字段，卡方和 Cramér's V 更适合没有做分箱的类别型字段，KS 和 Lift 更接近最终业务口径。四个指标方向一致时我才放心，只有一个突出时我会去查它为什么突出。

### 分箱的三条硬约束

不管用等频、等距还是卡方分箱，产物必须满足三条：每箱样本占比不低于 5%，否则 WOE 估计的方差太大；WOE 与坏账率单调，不单调说明分箱在拟合噪声；缺失、负数、特殊值各自单独成箱。边界一旦确定就固化进配置，随模型版本入库，线上按同一套边界做 `CASE WHEN`。

## 三、稳定性分析

### PSI 的公式与阈值

PSI 比较同一个字段在两个时期的分布差异，基准期通常是开发期，对比期是最近的自然月。

```
PSI = Σ_i ( A_i - E_i ) × ln( A_i / E_i )

A_i = 对比期第 i 箱的样本占比
E_i = 基准期第 i 箱的样本占比
```

它是一个近似对称的散度，本质上是两个方向 KL 散度之和的近似，所以 A 与 E 互换位置结果接近但不完全相等。工程上我固定基准期在前、对比期在后。

| PSI | 判断 | 动作 |
| --- | --- | --- |
| 小于 0.1 | 稳定 | 不动，正常监控 |
| 0.1 到 0.25 | 轻微漂移 | 记录并连续观察两到三个周期 |
| 大于 0.25 | 显著漂移 | 单独复看，评估重新分箱或限制使用 |

### 四个容易做错的地方

一是重新分箱。PSI 必须用开发期固化的边界，如果每次监控都按当期数据重新分箱，分布差异会被分箱本身抹平，指标永远好看。

二是小样本放大。某一箱在基准期占比很低时，PSI 会被这一箱主导。我会给每箱设最小样本量，占比为 0 的情况加一个极小的平滑项，同时对样本量不足的周期直接标注不可用。

三是只看取值漂移，不看缺失率漂移。实际经验里，缺失率的跳变往往比取值分布漂移出现得更早，尤其是依赖三方数据的字段。我会把缺失率单列一个时间序列盯。

四是用滚动基准。基准期应该固定在开发期，不要每月滚动更新，否则漂移会被基准自己吸收，等于没监控。

### 把 IV 和 PSI 放在一起看

单看任何一个指标都会做错决定，两个一起看才形成处置逻辑：

| | IV 高 | IV 低 |
| --- | --- | --- |
| PSI 低 | 主力变量，保留 | 剔除，或只作为业务规则 |
| PSI 高 | 复看，优先重新分箱或缩短更新周期 | 直接剔除，不要再花时间 |

## 四、特征相关性与多重共线性分析

### 相关性只是共线性的一个侧面

相关系数衡量两两之间的关联，常用三种：

```
Pearson   r = Σ(x_i - x̄)(y_i - ȳ) / sqrt( Σ(x_i - x̄)² × Σ(y_i - ȳ)² )
Spearman  对 x、y 分别取秩之后，再算 Pearson
Kendall   基于一致对与不一致对的数量
```

Pearson 只抓线性关系，一个字段是另一个的平方时，Pearson 可能接近 0 但信息高度重叠，所以我会同时看 Spearman。类别型字段之间用 Cramér's V，类别型与数值型之间我会把数值型分箱后再算。

需要注意的是，两两相关系数低不代表没有多重共线性。三个字段各占三分之一权重加起来等于第四个字段，任意两两相关性都不高，单变量回归也不显著，但联合起来会把系数方差推得很大。所以两两相关只能做粗筛，真正的判断要靠 VIF 和条件数。

### VIF、容差与条件数

```
对第 j 个特征：X_j ~ 其余全部特征 做线性回归
R_j² = 该回归的决定系数
VIF_j = 1 / (1 - R_j²)
容差_j = 1 - R_j² = 1 / VIF_j

条件数 κ = sqrt( λ_max / λ_min )，λ 为自变量相关系数矩阵的特征值
```

VIF 的直观含义是系数方差被膨胀了多少倍。因为 `Var(β) = σ² (XᵀX)⁻¹`，而 `(XᵀX)⁻¹` 的对角元里就含 `1 / (1 - R_j²)` 这一项，所以 VIF 从 1 涨到 10，系数标准误大致涨三倍多，显著性检验随之失效。

| 指标 | 关注线 | 严重线 | 说明 |
| --- | --- | --- | --- |
| VIF | 5 | 10 | 超过 10 说明该变量可被其余变量高度解释 |
| 容差 | 0.2 | 0.1 | VIF 的倒数，越小越糟 |
| 条件数 | 10 | 30 | 反映整体病态程度，比两两相关更全局 |
| 相关系数绝对值 | 0.6 | 0.7 到 0.8 | 粗筛用，弱相关不等于无共线性 |

### 我的去冗余流程

我不用「删到只剩一个」这种粗暴做法，而是做相关性聚类：把所有候选变量放进一个层次聚类，距离用 `1 - |Spearman|`，切一个阈值，每个簇里保留一个代表。

保留谁，按这个优先级判断：跨期稳定性最好、业务解释最直接、取数成本最低、缺失率最低。IV 最高只是其中一个考量，因为同一簇里的变量区分度本来就相近，多出来的那一点 IV 常常是噪声。

还有两个细节。第一，相关性要在 WOE 变换之后再看一遍，因为入模的是 WOE 值，变换会改变相关结构，有时原始值高度相关的两个字段，WOE 之后相关性会明显下降。第二，我不在主成分上建评分卡，虽然 PCA 能一次消掉共线性，但每个主成分是全部字段的线性组合，系数没法向业务和监管解释，这在信贷场景里是硬伤。

## 五、同一套分析在 LR 和树模型里的差异

前面四步是共通的，但每个环节在两个模型族里的重要程度和做法差别很大。这张表是我实际执行时的对照：

| 环节 | LR 评分卡 | LGB / XGB / CatBoost |
| --- | --- | --- |
| 缺失值 | 缺失单独成箱做 WOE，或填充后加一个缺失指示变量 | 原生处理：XGB 为缺失学一个默认分支方向，LGB 分到增益大的一侧，CatBoost 用 Min 策略 |
| 类别特征 | WOE 编码，必须有监督，且依赖分箱 | CatBoost 原生 ordered target statistics，LGB 与 XGB 用 target encoding 或 one-hot |
| 分箱 | 强制要求，且要单调、每箱占比够 | 非必须，可作为先验；业务合规场景改用单调约束 |
| 非线性 | 只能靠分箱加 WOE 近似表达 | 树分裂原生表达，交互项自动得到 |
| 异常值 | 分箱后自然钝化，重点是边界别被极端值吃掉 | 不敏感，但极端值仍会影响叶子均值 |
| 共线性 | 必须处理，VIF 与条件数都要过关 | 预测层面不敏感，但重要性会被相关的特征分摊稀释 |
| 特征筛选 | IV 加相关性聚类加逐步回归或 L1，一般 12 到 20 个 | gain、permutation、SHAP 加前向或后向搜索，数量可到上百 |
| 过拟合控制 | 变量数少，配合系数显著性检验与 L2 正则 | 树深、叶子数、最小叶子样本、学习率、行列采样、L1/L2、早停 |
| 稳定性 | 变量 PSI 加系数跨期漂移 | 特征 PSI 加 SHAP 贡献漂移，树结构本身换种子就会变 |
| 可解释性 | 系数即权重，监管友好，可直接写进制度 | TreeSHAP 与部分依赖，需要额外核对方向是否符合业务常识 |

### LR 评分卡的实际操作序列

1. 描述统计初筛，剔掉缺失率大于 90% 与单值占比大于 95% 的字段
2. 只在训练期计算 IV，取 0.02 作为入口线做粗筛
3. 有监督分箱：等频起步，再按业务边界微调，保证单调、缺失单独成箱、每箱占比不低于 5%
4. 做 WOE 变换，在变换后的值上重算相关性
5. 相关性聚类去冗余，每簇保留一个代表
6. 复查 VIF 与条件数，VIF 大于 10 的变量找出主因再决定去留
7. 逐步回归或 L1 收缩定最终变量表，逐个核对系数符号与业务方向
8. 跨期验证：OOT 的 KS、各变量 PSI、系数跨期稳定性
9. 分数校准，固定基准分与 PDO

最需要提醒的是第 7 步。LR 的系数在共线性下极不稳定，换一个训练窗口就可能符号反转，一个符号反了的变量在业务评审上是过不去的，它比掉一点 KS 更致命。

### 树模型的实际操作序列

1. 描述统计同样要做，但缺失与异常可以不做重加工，只需确认缺失本身携带信息
2. 单变量 IV 依然值得算，用来和树给出的重要性交叉验证，而不是直接决定入模
3. 稳定性用时间切分的滚动验证来看，比单点 PSI 更能反映趋势
4. 相关性不强制处理，但聚类去冗余能降低重要性稀释与训练成本，值得做
5. 训练时用早停加正则，盯住训练集与验证集的 gain 曲线是否分叉
6. 解释用 TreeSHAP，重点核对特征方向是否与业务常识一致
7. 合规场景加单调约束，把业务先验写进模型
8. 输出概率做校准，树的原始概率通常偏极端，Platt 或 isotonic 回归都可以
9. 固化特征口径与分箱边界，保证线上线下一致

这一步里坑最多的是重要性。gain 重要性天然偏袒高基数与连续特征，两个高度相关的强特征会互相抢分裂点，换一个随机种子，两者的重要性排序可能直接对调。我会用 permutation importance 和 SHAP 交叉验证一遍，重要的变量至少要在两种口径下都靠前。另外 CatBoost 的 ordered target statistics 是为了解决类别特征编码的标签泄漏，这也是它在类别特征多的场景下往往比 LGB 更省事的原因。

## 一份可以照着走的检查清单

- 标签口径与表现期先对齐，没走完表现期的样本整段丢弃
- 特征在申请时点可获取，且不依赖申请后的行为
- 缺失率、单值占比、特殊值三段先过一遍
- 按业务含义分组看坏账率，核对方向是否符合常识
- 只在训练期算 IV，OOT 只做复核
- 分箱单调、每箱占比不低于 5%、缺失单独成箱
- 入模相关性用 WOE 变换后的值算
- VIF 与条件数一起看，不要只看两两相关
- 变量 PSI 与缺失率漂移同时监控，基准期固定在开发期
- 树模型的重要性至少用两种口径验证，并检查换种子是否稳定

特征分析没有一步能跳过，但顺序可以优化。我的习惯是先用最便宜的手段淘汰掉大部分字段，再对剩下的少数做最贵的那一步。真正进入最终变量表的通常只有十几个，而这十几个字段在每个环节都被反复看过至少一遍。
