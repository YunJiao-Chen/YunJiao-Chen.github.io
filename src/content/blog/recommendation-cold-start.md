## 冷启动不是模型问题

我负责过的推荐场景里，冷启动带来的损失一度占整体指标缺口的三成。但复盘时我发现，把它当成「模型效果不好」是错的。新用户没有行为序列，任何依赖协同信号的模型都无米下锅。这时候要解决的是信息获取问题，不是建模问题。

我把冷启动拆成两类，它们的解法完全不同。新用户缺的是「这个人喜欢什么」，新物品缺的是「这个东西会被谁喜欢」。前者靠问和猜，后者靠内容和投放。

## 新用户：先用规则撑住，再用模型接管

新用户的前三次会话是信息最密集的窗口。我的做法是把生命周期切成三段，每段用不同的策略。

| 阶段 | 可用信号 | 主力策略 | 目标 |
| --- | --- | --- | --- |
| 首次会话 | 注册渠道、地域、设备 | 渠道热门加全局热度 | 保证不出错，点击率不崩 |
| 前三次会话 | 少量实时点击 | 多路召回加权融合 | 快速收敛兴趣 |
| 稳定期 | 完整行为序列 | 个性化排序模型 | 提升长期留存 |

第一段的关键词是「不出错」。新用户对推荐的容忍度最低，一次离谱的推荐就可能让他直接离开。所以首屏我宁愿用保守的热度榜，也不用置信度很低的个性化结果。

第三段的切换时机不能只看会话数，还要看行为密度。我们后来改成「累计有效行为数超过 20 条」才切换到个性化主模型，切换前用影子模式对比两边的排序结果，确认没有系统性偏差。

## 多路召回与兜底

冷启动阶段我没有只用一路召回，而是并行跑四路，再用一个轻量模型做融合。

```python
RECALL_ROUTES = [
    ('hot_global', 0.30),      # 全局热度，兜底
    ('hot_channel', 0.25),     # 渠道内热度，解决人群偏差
    ('content_sim', 0.30),     # 内容相似，解决新物品
    ('realtime_click', 0.15),  # 实时行为，仅在有信号时生效
]

def fuse(routes: dict[str, list[tuple[str, float]]], weights: dict[str, float]):
    scores: dict[str, float] = {}
    for name, items in routes.items():
        w = weights[name]
        # 每路先做 min-max 归一，避免某一路量纲压倒其他路
        if not items:
            continue
        lo = min(s for _, s in items)
        hi = max(s for _, s in items)
        span = (hi - lo) or 1.0
        for item_id, s in items:
            scores[item_id] = scores.get(item_id, 0.0) + w * (s - lo) / span
    return sorted(scores.items(), key=lambda kv: -kv[1])
```

这里有两个容易忽略的点。一是归一化，不同召回路的分数尺度差好几个数量级，不做归一直接加权等于只有一路生效。二是兜底必须永远有结果，当所有路都返回空时要用运营配置的保底列表，不能让接口返回 500。

## 探索与利用：给新物品一个公平的起点

新物品的问题是曝光机会被热门物品吃掉。我们上线过一版纯利用的策略，结果一周后新物品的曝光占比只有 2%，形成恶性循环。

解法是预留固定比例的探索流量，我一般设 5% 到 10%，并且用 `Thompson Sampling` 而不是固定比例的随机曝光，让不确定性高的物品获得更多试探机会。

```python
import numpy as np

class ThompsonBandit:
    def __init__(self, n_arms: int):
        self.alpha = np.ones(n_arms)
        self.beta = np.ones(n_arms)

    def select(self) -> int:
        samples = np.random.beta(self.alpha, self.beta)
        return int(np.argmax(samples))

    def update(self, arm: int, reward: int) -> None:
        self.alpha[arm] += reward
        self.beta[arm] += 1 - reward
```

> 探索流量的效果评估不能用点击率衡量，因为探索天然会拉低点击率。要用的是「探索带来的新增高质量物品数」和「探索流量在后续周期的留存贡献」。

## A/B 实验该看什么指标

冷启动实验最容易犯的错是只看点击率。新策略往往在点击率上略输，但在留存和多样性上赢。我固定看四组指标：

- 短期：首屏点击率、人均消费条数，判断有没有把用户赶走
- 中期：次日与七日留存、回访率，判断兴趣是否收敛
- 长期：新物品的曝光与转化占比，判断生态是否健康
- 护栏：接口 P99 延迟、空结果率，判断工程是否拖后腿

实验周期至少覆盖两个完整的周中加周末，因为冷启动用户的到达节奏在工作日和周末差异极大。我们有过一次实验在工作日跑出正向结论，周末上线后直接翻车，教训很直接。

最后一点经验：冷启动策略的价值不在于把新用户的第一印象做到极致，而在于尽快让用户脱离冷启动状态。衡量它好不好，要看它把自己淘汰得有多快。
