## 先把链路画出来

刚入行时我以为评分卡就是调一个 `LogisticRegression`。真正做过一轮线上迭代才发现，模型拟合在整个链路里大概只占两成工作量。剩下的八成分别落在样本定义、特征加工、跨期验证和分数校准上，而恰恰是这些环节决定了卡片能不能用。

我把自己在消费信贷场景里的链路固定成了六步，下面按顺序展开。

| 阶段 | 主要产物 | 最容易出问题的地方 |
| --- | --- | --- |
| 样本定义 | 表现期与观察期切分 | 表现期不足导致坏样本被低估 |
| 特征加工 | 宽表与分箱规则 | 分箱边界依赖全量数据，线上无法复现 |
| 变量筛选 | IV 与相关性清单 | 只按 IV 排序，忽略业务可解释性 |
| 模型拟合 | WOE 系数与截距 | 直接用原始值入模，系数符号反直觉 |
| 跨期验证 | 分时间段的 KS 与 PSI | 只在随机切分上验证，跨期一测就崩 |
| 分数校准 | 标准分与概率映射 | 上线后分数区间含义与开发期不一致 |

## 样本切分：时间维度优先于随机维度

新手最常见的做法是 `train_test_split(random_state=42)`。这在信贷里几乎没有意义，因为业务是随时间的分布漂移的，随机切分会让同一时期的样本同时进入训练和验证，验证指标虚高。

我现在的做法是按申请月份切：用 2024-01 到 2025-03 的申请建卡，留 2025-04 到 2025-09 做跨期验证，中间刻意留一个月的间隔月，避免标签泄漏。间隔月的意义在于，表现期通常需要 6 个月，用最后一个月建的卡会污染紧邻的验证期。

```python
import pandas as pd

def time_split(df, train_end='2025-03', oot_start='2025-05'):
    apply_month = pd.to_datetime(df['apply_month'])
    train = df[apply_month <= train_end]
    oot = df[apply_month >= oot_start]
    # 表现期没走完的样本直接丢弃，不要用 0 填充
    assert train['bad_flag'].notna().all()
    return train, oot
```

## WOE 分箱：规则要能搬到线上

分箱的产物不是几个区间，而是一份可以固化的映射表。业务方上线时只需要按边界做 `CASE WHEN`，所以边界必须是单调、无重叠、且对缺失单独设箱的。我习惯在分箱后立刻做三件事：

- 检查每个箱的样本占比，低于 5% 的箱合并，否则 WOE 估计方差过大
- 检查 WOE 与坏样本率的单调性，交叉验证分箱是否只是过拟合噪声
- 把边界和 WOE 写进配置文件，随模型版本一起入库

> 经验上，一张卡片有 12 到 18 个入模变量就够了。变量再多，KS 提升往往不到 0.01，但线上取数成本和排查难度会成倍上升。

## 跨期验证看什么

OOT 上的 KS 通常比训练集低 0.02 到 0.05，属于正常范围。如果掉超过 0.08，我会优先怀疑两件事：一是特征口径在验证期发生过变更，二是分箱边界吃到了时间趋势。后者可以用 PSI 快速定位，对每个变量算训练期和 OOT 的分数分布差异，PSI 超过 0.1 的变量要单独复看。

## 分数校准：让分数区间有确定含义

逻辑回归输出的是概率，但业务方要的是分数。我做校准时会固定基准分和 PDO，让每个分数段的预期坏账率可以横向比较：

```python
import numpy as np

def to_score(prob, base_score=600, base_odds=30, pdo=50):
    odds = (1 - prob) / prob
    factor = pdo / np.log(2)
    offset = base_score - factor * np.log(base_odds)
    return offset + factor * np.log(odds)
```

上线后每个月我都会拿实际坏账率回填一次分数段对照表。只要某个分数段的实际值偏离预期超过 30%，就先查数据口径，再谈重训。

## 上线前的检查清单

- [x] 分箱边界与 WOE 映射已随模型版本入库，线上可复现
- [x] OOT 的 KS、AUC 与训练集差距在可解释范围内
- [x] 缺失值、极值、新出现的枚举值都有兜底分箱
- [x] 分数段对照表已与业务、策略两边对齐
- [ ] 每月回填一次实际坏账率，偏差超阈值时触发复盘

这张清单我贴在工位上，每次上线前逐条打勾。评分卡的技术难度不高，难的是把每一个边界条件都想到，并且留在文档里。[^1]

[^1]: 关于 WOE 与 IV 的推导细节，可以参考 [scikit-learn 的预处理文档](https://scikit-learn.org/stable/modules/preprocessing.html) 里关于分箱与编码的部分。
